Syntax editor panes

This page describes the panes of the syntax editor, except File Mapping and Outline. To open the editor, see Make or change a syntax. For syntaxes that use tree-sitter, Outline is locked and the Highlighting section shows only a locked Built-in item, because those rules can’t be changed.

Highlighting

The Highlighting section of the sidebar has a pane for each kind of text. The theme gives each kind its color.

Graupel applies the panes from top to bottom, so when text matches two of them, the lower one wins. Strings and comments also come from the Delimiters pane.

Each pane lists rules. Click the Add (+) button, then fill in:

  • Begin String: the word or pattern to match. A rule without one is skipped.

  • End String: if set, everything from the begin string to the end string matches, such as a <!-- … --> comment.

  • RE: treats both strings as regular expressions. Both are patterns or both are plain text.

  • IC: ignores case, so abc also matches ABC.

  • Multiline: lets a match run across lines.

  • Description: a note for yourself.

Plain words, with no end string and RE off, are also offered as suggestions unless the Completion pane lists its own words.

Delimiters

Delimiters tell Graupel how the language marks comments, strings, and blocks. They’re used for highlighting, for Text > Comment, for matching quotes and brackets, and for indenting as you type.

  • Inline comment: what starts a comment that runs to the end of the line, such as ! in Boreas or // in Swift. Select Line Start Only if it counts only at the start of a line, after any spaces.

  • Block comment: the Begin String and End String of a comment that can span lines, such as /* and */. Select Nest if the language allows comments inside comments.

  • String delimiters: the quotes around strings. Multiline lets a string span lines, Escape Character is the character that lets a quote appear inside, usually \, and Prefixes lists letters that must come right before the quote, such as r,f,b for Python’s r"…". Add more than one row for more than one quote style, such as "…" and """…""".

  • Character delimiters: the same for character literals, such as 'a'.

  • Block delimiters (under Indentation): when a line ends with a Begin String, such as { or then, pressing Return indents the next line one more level. If the End String, such as }, is right after the insertion point, Graupel also puts it on its own line at the original indentation. Leave End String empty for languages like Python, where a block starts with : and has no closing word. Select IC for languages where case doesn’t matter.

    Some languages start a block with a word at the start of the line instead, such as do i = 1, n or function f(x). For those, select RE and make Begin String a regular expression. Graupel indents when it matches anywhere in the line before the insertion point, so you can also rule out one-line forms. For example, Boreas uses ^\s*case\b(?!.*->) to indent after case 1, 3 but not after case 1 -> "small".

    Graupel doesn’t move a closing word like end back out as you type it, so outdent that line yourself.

Default indentation (under Indentation) sets spaces or tabs and a width for new documents in this syntax, such as 2 spaces for Boreas. An .editorconfig, a file’s own indentation, or a mode for the syntax wins over it. See where indentation comes from.

When a syntax has both inline and block comments, Toggle Comment uses the inline one. With several of either kind, it uses the first in the list.

Completion

Words listed here are added to the suggestions in documents with this syntax. Fill in Completion with the word, and optionally a Type. If the list is empty, Graupel uses the plain words from the highlighting panes instead. Whether syntax words are suggested at all is set in Mode settings. See Complete words.
